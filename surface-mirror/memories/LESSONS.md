A stub binary in a test is the right positive control here: it proves the transport without depending on a provider quota that can run out at any time - evidence: the defect was reproduced exactly by putting the old line back, and tests/test_provider_codex_stdin.py now fails on it
- 2026-10-26 [technical] The last line of stderr is not the reason. The Codex CLI's stderr is full of unrelated noise - a stale MCP server can log a fatal 404 there - so taking its last line reported '404' for a provider that was really out of plan quota, and the router classified it as nomodel. The reason is in the event stream: a turn.failed event carries the true message. Read the event, not the noise - evidence: chatgpt was reported as nomodel while the real message was 'You've hit your usage limit'
- 2026-10-26 [providers] A plan cap is BLOCKED, not FAILED, and a caller that asked for JSON must ALWAYS get JSON. 'You've hit your usage limit, upgrade to Pro' means the credential is valid and the subscription is real but the plan will not serve more right now. The router printed a bare line on stderr and exited, so the routing proof, the review rotation and the panel all received an unparseable stream and could not tell a quota from a defect. A rate limit is deliberately NOT blocked - that one is transient. The failed call must carry the per-provider attempts so the reason is visible - evidence: the ChatGPT proof now skips with the quota reason printed instead of failing
- 2026-10-26 [git] The old history kept for the push must not be counted as a survivor. Moving the cleanup of refs/original/* to AFTER the push - so the push would still have a common ancestor - meant the survivor count, which used `--all`, saw the old commits and reported 'STILL PRESENT - not pushing' for a rewrite that had worked perfectly. Count the REWRITTEN refs (`--branches --tags`) for the survivor check and keep `--all` for the audit - evidence: the faraday rewrite was rejected by its own check, and 85 commits had been rewritten correctly
